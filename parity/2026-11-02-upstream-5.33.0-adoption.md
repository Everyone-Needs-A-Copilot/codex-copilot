# Reviewed upstream adoption: Claude 5.30.1 to 5.33.0

Scope: Claude Copilot 5.31.0, 5.32.0 and 5.33.0 (cc 2.18.0, tc 2.11.0, agents 5.13.0, commands 5.10.0). This is an explicit review and port, not a no-port-needed attestation. The 5.33.0 source is the integration commit `c9337dd` on `release/5.33.0-tiered-verification`.

| Upstream change | Native disposition |
|---|---|
| tc 2.11.0 verification tiers: `tc task tier`, `tc task attest` (T1: `--in`, `--present`, `--absent`, `--load`; T2: `--render`, `--checks`; `--source` as `VALUE=file:line \| WP-id \| pablo:<quote>`), `tc task qa-packet`, attestation and approval-manifest tables, tier branch in `check_task_qa` | Shared tool. Codex runs the same `tc`, so approval and completion enforce tiers with no Codex code. `VERSION.json` and `parity/claude-baseline.json` require tc 2.11.0 and list the three commands. |
| `.claude/agents/_shared/verification-policy.md`: Verification Tiers table first, UI-behavior row scoped to T3, `pablo:<quote>` source form | Ported byte for byte. `scripts/sync-work-lifecycle.py` now carries two canonical files (work lifecycle and verification policy); `--check` fails on any drift. The previous reworded Codex policy copy is replaced. |
| `me.md`, `qa.md`, `ta.md`, `protocol.md`: QA agent only for T3 and escalations, T1/T2 finish with `tc task attest`, tier before the done block, `Tier:` line | Ported to the `$me`, `$qa`, `$protocol` and `$ta` skills; `$me`, `$qa` and `$protocol` read the policy copy, and `$ta` names the tier and its test requirement for each implementation task. |
| `.claude/hooks/pretool-check.sh` and `subagent-stop.sh`: gate state derived from `tc task check-qa`, header variants, rework fallback | Claude-specific. Codex has no tool-blocking hook. `scripts/copilot-gate.sh` already calls `tc task check-qa --json` and requires `approved` with an integer `work_product_id`, which an attested T1/T2 task returns, so no gate code changes; the legacy regex fallback applies only when `check-qa` is missing and describes T3 packets. |
| 5.31.0 `cc resources` managed synthetic test databases; `/setup` and `/update-copilot` install tc through `tools/tc/install.sh` | Shared cc tool and Claude command wording; Codex setup skills never ran `pip install -e` for tc. No port. |
| 5.32.0 organization skills distributed to Claude and Codex by `cc update` | Shared cc tool; Codex receives the skills through the same distribution. No port. |
| Version and manifest bumps | `VERSION.json`, plugin manifest, catalog and both pack manifests advance to 0.15.0; the catalog schema is unchanged. |

Obsolete checks updated, with the same coverage kept: `tests/test_verification_policy.py` no longer requires the Codex-only change-basis token `owner-requested-obsolete-check` inside the policy copy, because the canonical neutral policy cannot carry it; the token is still required in `AGENTS.md`, where the integrity gate's `--test-change-receipt` contract lives, and the test now also pins the tier table, flags and skill references. `tests/test_work_lifecycle.py` fixtures now provide both canonical source files because the sync CLI carries both, and gain policy byte-equality, drift and missing-source tests.

`.claude/evals/me/me-struct-001.yaml` asserted the literal route `$qa` always, which the requested tier policy retires. Old expectation: `$qa` always routes implementation to QA. New expectations: `$qa` for T3 and escalated work, and T1/T2 finish with `tc task attest` and no QA specialist; both phrases are asserted in the `$me` skill.

Publication and live consumer acceptance remain separate from source adoption.
