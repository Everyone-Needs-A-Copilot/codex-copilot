This records the initial trial. [Shared gap closure](03-shared-gap-closure.md)
supersedes the initial version and native-dispatch holds below.

Validation exercises the shared design adapter and native instruction integration,
not a claim that all CSE releases or all products have improved.

  checks, including source/stylesheet

## First rendered trial

An existing Control Tower support-report UX walkthrough was copied into an isolated
trial workspace. Chromium 151 through locally inspected Playwright 1.62 APIs
rendered four states at two widths in light/dark mode: 16 inspected combinations,
no page errors and no horizontal page overflow at 390px. Keyboard theme and state
navigation worked. The shipping SwiftUI application and original walkthrough were
unchanged.

Initial design review found a normal-size primary-button label at **2.473:1** in
dark mode and **4.493:1** in light mode. The static scan reported an uppercase-text
candidate but did not report this dynamically rendered button contrast defect.
An isolated CSS candidate and actual-capture comparison demonstrate the correction;
this is not product-owner acceptance or evidence that shipping native UI has that
defect. The original trial remains rejected for its required contrast criterion.

## Explicit limits

Native feedback is registered in the two framework workspaces and its adapters
are replay-tested. A fresh Claude/Codex session must still prove real event
dispatch; an already-running session is not assumed to reload its manifests.
Other consuming projects require their normal update/activation workflow.

During this initiative, separate Claude work committed the prior evidence handoff
as framework 5.15.0 / tc 1.4.0. Its eleven changed instruction surfaces were reviewed:
seven design specialists/protocol carry the new design sections; cco/cw/ind and the
taste-reading specialists carry explicit project/lens precedence; shared optional
context retains once-per-task selection and visible fallback behavior. Codex now
uses the tc task authority when advertised, with a visibly labeled legacy artifact
inspection path retained for compatibility. An authoritative rejection cannot fall
back to older WPs. Version/content baselines were recaptured only after these native
ports. Existing tests were preserved. See the parity decision for the boundary.

The implementation is locally active, cc 2.12.16, and unpublished. The prior Claude
release-preparation document now explicitly requires revalidation of the extended
candidate. No signed tag, release, fleet-wide deployment, independent reviewer,
owner preference promotion or measured net productivity gain is claimed.
