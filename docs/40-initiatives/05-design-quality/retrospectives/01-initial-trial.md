# Initial design-quality trial

The complete capability is useful because it connects several kinds of evidence.
The first Control Tower prototype review found a rendered contrast issue that the
static detector missed. A detector-only gate would have directed attention toward
an uppercase label while leaving the more material button problem unresolved.

The surface contract kept the job and four recovery states explicit. Initial
judgment was recorded before scanning. The browser exercised real themes and
widths; content hashes bound the screenshots to the copied prototype. An isolated
candidate made the change reviewable without silently modifying the native product.
The report keeps failed required criteria as gaps even when scan execution succeeds.

This supports retaining rendered inspection and task-bound QA. It does not establish
causal productivity gains from the framework, confirm the shipping application's
accessibility, or authorize a global font/color policy. Native-language fallback
also matters: a web detector cannot certify SwiftUI merely because both produce UI.

Next real-work evaluations should preserve comparable baselines and criteria,
record owner acceptance and rework, distinguish actual defect fixes from aesthetic
preferences, and count false-positive changes. Keep per-runtime dispatch evidence,
release propagation and design effectiveness as separate claims with their own
task-bound observations.
