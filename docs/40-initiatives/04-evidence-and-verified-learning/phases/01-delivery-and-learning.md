# Delivery and learning

TASK-11 and TASK-12 own implementation and verification; status lives in `tc`.

The smallest sufficient evidence packet is one observable criterion, input/state,
expected result, observed result, tested identity, baseline artifact (or an explicit
missing-baseline reason), local artifact/command and untested cases. Required cases
that remain untested cannot support approval. QA interpretation remains explicit;
the existing artifact-marker gate does not semantically verify a screenshot.

Taste remains personal. A receipt names a minimized local source, exact quote and
line range, hash, session/source identity, observation date, scope and explicit vs
inferred origin. Legacy counters remain readable but cannot satisfy verified
promotion. No repeated text or silence creates independent evidence. Two distinct
sessions support an inference; one verified explicit standing instruction may use
recorded `--force`, still requiring concrete owner approval. Conflicting active
rules must be retired or the candidate narrowed before promotion.

Mechanism checks use disposable synthetic sources, never mined private history.
Approval flags attest the operator's recorded owner decision; they are not an
identity authentication system. The private corpus's README documents this limit.
