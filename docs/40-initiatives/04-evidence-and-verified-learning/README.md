## Outcome sought

Make delivery claims reproducible, personal learning traceable, and optional
context costs observable. Effectiveness on real work remains an evaluation
question; installing mechanisms is not evidence of improved outcomes.

## Adopted design

- Both frameworks' `ta/me/qa` playbooks carry the criterion/result/identity/baseline
  evidence handoff. Shared operations and worktree isolation depend on actual
  duplication, responsibility and collision risk.
- The existing private `scripts/taste` validates deliberately selected receipts,
  independent sessions, owner approval and conflicts, and regenerates the active
  index on retirement. No real rules are inferred or promoted by this initiative.
- Shared `cc skill select` explains selection, deduplicates returned content and
  retains explicitly required skills even over the optional character budget.
- `cc doctor --runtime-details` reports project-local declaration, installation,
  source identity and unknown runtime trust. `--exercise-runtime` directly probes
  native Codex hooks in disposable state. Direct probes do not prove lifecycle
  dispatch, global runtime configuration or runtime enforcement.
- `cc eval adoption-freeze` / `adoption-check` extend existing evaluation reporting
  with frozen inputs and conservative pilot gates. Copilot Benchmark remains the
  model runner; this is an observation validator, not another runner or evaluator
  authority. Neither a pilot signal nor a provider score replaces `tc` QA.
